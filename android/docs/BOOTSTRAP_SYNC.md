# Initial wallet sync in the mobile candidate

The foreground-only Core option now has a narrow first-sync exception. A newly created, restored, imported, or previously unmarked local wallet keeps the already requested foreground service running after the screen turns off while connectivity is permitted. Manual **Stop sync** and the Wi-Fi-only preference still stop network work. Background status reads are authenticated; signing, sending, and an unlocked wallet UI still require the visible app.

Core reports a recent successful cumulative-work comparison with a connected peer and the wallet scanner's exact canonical chain tip/hash. With foreground-only mode enabled and the wallet in the background, Android stops Core after readiness, then commits completion only when a private nonce-bound shutdown receipt confirms a successful wallet save and the same wallet and canonical tip. A crash, failed save, forced stop, changed tip, or missing receipt leaves the wallet pending. The record is scoped by network and wallet filename; create, restore, and import clear it before changing the wallet. With foreground-only mode disabled, Core keeps running and does not enter this auto-stop path.

Android can kill the process while the screen is off. The service is not restarted in the background after that. This feature does not persist a new wallet password; the existing optional biometric vault has its own Keystore-encrypted password storage. API lock alone leaves loaded wallet keys and a cloned password in the resident Core process. Opening and unlocking the wallet resumes its saved scan. If Core restarts without a loaded wallet, a dismissible notification asks the user to open the wallet to resume initial sync; it does not assert that the final chain tip was saved. Cached balances remain dated and cannot be used as a current balance or to send offline.

The implementation uses a foreground service and no bright wakelock. It does not guarantee progress through Doze, denied connectivity, process death, or a peerless network. Device checks still need a disposable wallet and peer on Wi-Fi: screen off during chain download and wallet scan, Wi-Fi to cellular with mobile data disallowed, reconnect, manual Stop, process kill/reopen, and a complete scan followed by background pause. Measure battery use and restart cost before claiming savings.
