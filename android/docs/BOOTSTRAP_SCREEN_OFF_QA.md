# Disposable screen-off initial-sync acceptance

This test is an opt-in phase of `WalletBootstrapInstrumentation`. It is not part of the ordinary UI/persistence phase. The first controlled S22 run on 2026-10-19 exposed a fetched-block scan gap: authenticated chain height reached 2 while a fresh wallet scan remained at 0. Core patch 0011 adds wallet notification on that path. A second controlled run passed with the screen off: chain and wallet scan heights advanced together from 0 to 2, the nonce-bound shutdown proof and durable completion marker matched, Core remained stopped for the 20-second observation, and the marked testnet fixture was removed with the original OFFLINETEST preferences restored. This does not measure full mainnet sync, battery use, process death, or funded sends. The test requires an ARM64 Android device, validated Wi-Fi, the controlled-peer QA Core build, and a controlled **testnet** peer. It never sends a transaction or prints a wallet password, address, wallet ID, API cookie, or peer address.

The QA Core is compiled from the pinned mobile Core with ordered patches 0001–0011, then `qa/controlled-peer.patch`. First run `scripts/build-core-android.sh` into a fresh directory, then `scripts/build-core-bootstrap-qa.sh` with that reviewed build and a second fresh directory. Only a `-PbootstrapIntegration` OFFLINETEST debug build may package the QA output; the normal APK verifier rejects it. For testnet, Android passes a process-only `BLOCKNET_QA_TESTNET_PEER_ONLY=1` flag. Core requires exactly one private IPv4 TCP peer in `extra_peers`, skips public seed resolution, and refuses authenticated connections to other peer IDs. This setting is never persisted to the wallet or Core settings file. The QA build is not a release candidate.

The OFFLINETEST APK now has a blue **T** launcher icon and the label **Blocknet OFFLINETEST**. Its `blocknet:` VIEW alias is disabled, and its `MainActivity` ignores externally supplied payment links. The production APK keeps its original icon, label, and enabled payment-link alias. The two packages still have distinct Android UIDs and app-private data; they share the device loopback network namespace.

## Preconditions and fixture

- Obtain separate owner approval before updating or running `com.blocknet.wallet.offlinetest` on a physical device. `android/scripts/test-device.sh` targets production and must not be used for this test. Updating OFFLINETEST with `adb install -r` preserves its existing app data but replaces its code and may stop its process. Never uninstall, clear data, or replace its current wallet to make the fixture fit.
- The runner refuses an existing sidecar testnet directory, an `active.testnet` preference, a pending testnet send, an active sidecar Core, or a persisted sidecar sync request. An existing OFFLINETEST mainnet wallet remains outside the disposable fixture. The test changes the sidecar's selected network temporarily, creates only a fresh testnet directory, and restores its prior preferences after Core stops. A failed or killed run may leave that new fixture for inspection; a rerun refuses it.
- For the approved temporary OFFLINETEST setup, with Core stopped and the phone awake on validated Wi-Fi, run `-e phase pause-sidecar-request` before the test. It durably records the original values **and key presence** of the saved Start sync request, Allow mobile data, Foreground-only Core, and network. It then sets only those three sidecar policy choices to request off, mobile data off, foreground-only on. Run `-e phase restore-sidecar-request` after the test even if the test fails or its process dies. Restoration checks the unique fixture marker, stops only the marked disposable testnet Core, removes only its fixture/cache, and restores the exact original three choices and network. A failed cleanup leaves the receipt for inspection/retry. Verify the restored choices, stopped Core, and absent testnet fixture. Never use these phases on the production package.
- An existing OFFLINETEST mainnet wallet file is not read, overwritten, or deleted. The runner refuses an active mainnet saved-view session. The sidecar APK update can stop its process; if its wallet was open offline before the update, its owner may need to unlock it again afterward. The runner removes only the unique testnet fixture and saved-view cache it created; it does not clear the package's data or a prior wallet.
- Supply a dedicated testnet Core peer as a TCP multiaddress ending in `/p2p/<peer-id>`. The peer must hold at least two valid blocks above the sidecar's starting tip, remain connected, and release those blocks only after the instrumentation reports that the screen is off. Supply the peer's expected final tip as `targetHeight`; the runner rejects a fixture already at that height before or immediately after screen-off. A peer that releases all blocks too quickly may outrun the one-second observation loop and fail without implying chain corruption.
- Keep the device unlocked at the start. The test itself sends Android sleep/wake key events, then verifies the screen stays off during catch-up. It uses the sidecar's authenticated `/api/wallet/bootstrap` endpoint and checks the package, network, process ownership, chain height, wallet synced height, completion marker, and nonce-bound shutdown receipt. It waits 20 seconds after verified stop to detect an unexpected background restart. Do not use this instrumentation's polling interval as a battery measurement.

After the owner approves the isolated install and test, build the `-PbootstrapIntegration -PisolatedTestApplicationId=com.blocknet.wallet.offlinetest` variant, verify both APK package names and the launcher resources, and install only that app/test pair. Run `pause-sidecar-request`, perform the screen-off phase, then run `restore-sidecar-request` in a separate instrumentation process. The two-phase `qa-state-prepare` / `qa-state-verify` emulator check exercises durable preference restoration and fixture ownership without changing wallet preferences. The screen-off invocation is:

```sh
adb -s DEVICE shell am instrument --user 0 -w \
  -e phase screen-off \
  -e peerMultiaddr '/ip4/TEST_PEER_IP/tcp/TEST_PEER_PORT/p2p/TEST_PEER_ID' \
  -e targetHeight TEST_PEER_TIP \
  -e timeoutSeconds 900 \
  com.blocknet.wallet.offlinetest.test/com.blocknet.wallet.WalletBootstrapInstrumentation
```

The controlled peer should release its held blocks after the `PASS screen is off and first-sync exception remains pending` status. A pass requires **both** chain and wallet scan heights to advance after the off-screen baseline, the shutdown receipt to reach `targetHeight`, the durable completion marker to clear pending first sync, and Core to remain stopped while the screen stays off. If Android kills the app or the network changes, the run is interrupted and cannot claim success. Physical battery use, restart cost, real-world Doze, and funded-wallet compatibility require separate acceptance.

The connected x86_64 emulator can compile and exercise the sidecar UI/persistence phase, but `NativeRuntime.start()` intentionally refuses native Core on that ABI. It cannot establish ARM64 screen-off sync acceptance.
